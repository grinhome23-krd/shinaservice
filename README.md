# 🛞 ШинаСервис — онлайн-запись на шиномонтаж

Самодостаточный одностраничный сайт автосервиса: публичная онлайн-запись,
админ-панель и панель сотрудников с посменным графиком. Один HTML-файл без
сборщиков и зависимостей. Данные — в `localStorage` браузера, а при запуске
рядом [сервера с БД SQLite](#бд-сервер-sqlite-общая-база-для-всех) — в общей
базе, видимой всем устройствам.

## Возможности

### Единая точка входа
- Одна кнопка **«Вход»** в шапке (и ссылки в подвале) открывает одну форму **«Код доступа»**: сотрудник входит своим **ПИН-кодом**, администратор — **паролем** (демо: `admin123`), система распознаёт роль автоматически;
- Клиенту вход не нужен — запись на главной, свои записи — в «Моих записях» по телефону;
- В режиме БД сервер проверяет код на своей стороне (GET /api/db?code=…) и роль сотрудника/админа возвращается сервером.

### Публичная часть
- Каталог услуг с ценами и длительностью, запись в 3 шага (услуги → дата/время → контакты);
- Слоты с учётом рабочего графика, количества постов и перерыва 15 минут между записями;
- **Личный кабинет клиента** (раздел «Мои записи», вход по телефону записи): статистика за всё время (выполненные визиты, потрачено, ожидается к оплате, средний чек), сводка «Мои услуги» (сколько раз и на какую сумму), история всех записей с открытием подробностей по клику (статус, мастер, авто, услуги с ценами, журнал уведомлений);
- **Изменение записей клиентом**: неподтверждённую запись можно самим перенести (дата и свободные слоты с учётом занятых) и поменять услуги с пересчётом суммы; подтверждённую — отменить; все действия фиксируются в журнале записи, мастер перепривязывается по графику смен;
- Уведомления клиенту: экран успеха с кнопками «📅 В календарь» (ICS-файл-напоминание), «💬 WhatsApp» и «✈️ Telegram» с готовым текстом визита.

## БД: сервер с SQLite (общая база для всех)
- `server/server.js` — сервер **без внешних зависимостей** (Node.js ≥ 22.5, встроенный `node:sqlite`). Запуск: `node server/server.js` (порт 3000, переопределяется `PORT`). Отдаёт сайт и хранит все данные в `server/data/shina.db`;
- Автоопределение: сайт при загрузке проверяет `/api/ping` — если сервер есть, весь сайт работает **от общей БД** (записи, созданные клиентом на сайте, мгновенно видны админу и сотрудникам на любых устройствах; админ-правки сохраняются в SQLite и переживают перезапуск сервера). Нет сервера (например, GitHub Pages) — сайт работает как раньше, на localStorage;
- API: `GET /api/state` — публичная **обезличенная** копия (без пароля, ПИН-кодов, телефонов и имён клиентов — только то, что нужно для слотов и графика), `POST /api/bookings` — создание записи с сайта с проверкой занятости слота на сервере, `GET /api/my` — записи клиента по телефону, `POST /api/booking-op` — правки/отмена из личного кабинета, `GET/POST /api/db` — полный доступ только по коду доступа (ПИН сотрудника или пароль админа);
- Синхронизация: в режиме БД клиент опрашивает сервер раз в 15 секунд и обновляет открытые панели; при недоступности сервера изменения сохраняются локально с предупреждением;
- Безопасность: запускайте сервер в доверенной сети или за reverse-proxy с HTTPS; смените демо-пароль и ПИН-коды в настройках админки.

### Админ-панель (`admin123` по умолчанию)
- Дашборд: записи на сегодня, новые, выручка за месяц, график загрузки за 7 дней, смены мастеров; **клик по столбцу графика открывает день** — сводка по статусам и все записи с переходом в карточку;
- **Смены мастеров (вкладка)**: календарь месяца с мастером каждого дня (ротация / гибкий график / замена) и числом записей; клик по дню — назначение **замены мастера на конкретную дату** (с перепривязкой авто-записей дня), суммы смены и все записи с подробностями;
- **Выручка по сотрудникам**: «Итого · все мастера» одной строкой и затем каждый мастер отдельно — факт (выполненные заказы за месяц и всего) и ожидаемая сумма по утверждённым записям;
- **Прайс-лист для печати**: в «Услугах» кнопка «🖨 Прайс-лист для печати» — аккуратный документ А4: шапка с реквизитами, таблица по категориям, внизу дата составления, подпись ИП (Ф.И.О. задаётся в Настройках) и место для печати;
- **Гибкие смены**: в карточке сотрудника можно закрепить за ним выбранные дни недели — в эти дни смена его (несколько «гибких» чередуются по датам), в остальные дни работает общая ротация «через день»;
- Записи: фильтры (статус, период, мастер, поиск), смена статусов, редактирование, удаление, экспорт CSV/JSON, ручная запись клиента;
- Источник каждой записи — «онлайн» или «телефон» — в таблице, карточке записи и CSV-выгрузке;
- Статистика на главной: четыре цифры и подписи в шапке сайта редактируются в «Настройках» (пустые пункты скрываются);
- Услуги: добавление, редактирование, скрытие от клиентов;
- Расписание: рабочие дни, часы, интервал слотов, посты, праздничные дни;
- Настройки: данные сервиса, ИП для документов, статистика на главной, канал и шлюз уведомлений клиентам, смена пароля, резервные копии JSON.

### Уведомления
- **Сотруднику и админу** — всплывающее уведомление со звуковым сигналом о каждой новой онлайн-записи (браузерный push при выданном разрешении, иначе тост; звук — короткий двухтоновый сигнал, вкладка обновляется сама);
- **Клиенту** — автоматически при подтверждении или отмене записи уходит SMS или сообщение в мессенджер MAX: канал выбирается один раз в «Настройках», клиенту выбор не предлагается. Если указан URL шлюза (webhook), сообщение реально отправляется (POST JSON: phone, text, channel); без шлюза текст сохраняется в журнале карточки записи. Клиент видит в «Моих записях» отметку об отправке.

### Панель сотрудника (вход по ПИН-коду)
- Два сотрудника работают посменно — чередуются через день (дата старта и порядок настраиваются в админке), плюс гибкий график по дням недели для каждого;
- Записи автоматически закрепляются за мастером по дате визита; админ может назначить вручную;
- Сотрудник видит **только свои** записи и может: подтвердить, завершить, изменить (дата, время со свободными слотами, услуги с пересчётом суммы, контакты), отменить;
- **Запись по звонку**: кнопка «+ Записать клиента» и — прямо из календарного вида — «+ Записать на этот день» в таймлайне дня: форма с датой, свободными слотами и выбором мастера, **включая смену коллеги** (в день коллеги он выбран сразу с пометкой «на смене в этот день»; в таймлайне дня видны записи всех мастеров). Запись уходит в панель коллеги с уведомлением;
- **🏁 Завершить смену** (кнопка видна, когда сегодня смена сотрудника): подробный отчёт за день — все записи смены с клиентами, авто, услугами, суммами и статусами + итоги (выполнено, подтверждено, новые, отменено). Отчёт открывается в модалке и отправляется: в **MAX администратора** через шлюз уведомлений (если настроен), **на почту** (почтовый клиент с готовым письмом; адрес задаётся в Настройках → «Почта для отчётов о сменах») и в **PDF** (диалог печати → «Сохранить как PDF»);
- **Уведомления о новых записях**: бейдж «🔔 Новые» с числом непросмотренных записей, всплывающий тост при появлении новой записи (в том числе созданной клиентом в другой вкладке) и фильтр «Непросмотренные»;
- **Календарный вид**: кнопка «📅 Календарь» — месяц целиком с числом записей и полоской занятости рабочего дня по каждому дню; клик по дню показывает записи по времени (интервалы с учётом длительности услуг); листание месяцев, кнопка «Сегодня»;
- Выручка за **день / неделю / месяц** — только фактически выполненные заказы (факт) — плюс сумма по утверждённым записям («Ожидается») и счётчики заказов.

### Мобильная версия
- Полная адаптация: карточки вместо широких таблиц, полноэкранные модалки,
  крупные тап-таргеты, поля без автозума на iOS, горизонтального скролла нет.

## Демо-доступ

| Роль | Где входить | Пароль / ПИН |
|---|---|---|
| Администратор | кнопка «Админка» в шапке | `admin123` |
| Сотрудник Сергей | футер → «Панель сотрудника» | `1111` |
| Сотрудник Андрей | футер → «Панель сотрудника» | `2222` |

Пароли и ПИН-коды меняются в админке. Это демо: они хранятся в `localStorage`
открытым текстом — для боевого использования нужна серверная авторизация.

## Структура

```
index.html          — собранный сайт (открывается двойным кликом)
src/
  site_parts/       — исходники по частям (стили, HTML, JS)
  build_site.py     — сборка: python3 src/build_site.py src/site_parts index.html
  check_site.py     — быстрая проверка: JS-синтаксис, ссылки на id, мусорные строки
```

## Локальный запуск

Открыть `index.html` в браузере, либо:

```bash
python3 -m http.server 8000
# http://localhost:8000
```

## Деплой на GitHub Pages

1. Settings → Pages → Source: `Deploy from a branch`;
2. Branch: `main`, папка `/ (root)` → Save;
3. Сайт будет на `https://<логин>.github.io/<репозиторий>/`.

## Хранение данных

Все данные (записи, услуги, настройки, сотрудники) лежат в `localStorage`
браузера на устройстве пользователя. Резервная копия — «Настройки → Экспорт
JSON» в админке. Сброс браузера = сброс данных.
